About

Most of my work has been on apps that were already live. I moved them to Flutter and kept them running for the people who use them every day.

I started with Flutter at Majoo in 2020, helping move a native Android point-of-sale app to Flutter for both phones and tablets. Since then I've taken over a healthcare app from a previous vendor at Aleph Labs, helped migrate TRACtoGO from React Native at SERA, and now work on a white-label hotel app at Sentinel Tech.

I care about code the next engineer can work in. In practice that means a clear architecture, and fixing production issues at the cause instead of around it.

How I work

  1. Migrate without stopping the product

    Features keep working while the codebase changes underneath. I've done this with React Native, native Android and Kotlin apps.

  2. One codebase, many shapes

    Layouts that respond to the space they get, and brands that come from configuration instead of forks.

  3. Release is part of the job

    I handle store releases and app protection, and I stay on to fix what breaks after launch.

  4. Leave the code better

    Refactoring inherited code so the next feature costs less to build.

Sentinel Tech

2026 – Present

In development

One Flutter codebase, many hotel brands

Problem
Each hotel brand needs its own app with its own name, colors, fonts, icons and bundle ID. A separate codebase per brand would multiply every fix and feature.
My part
Worked with the backend and CMS teams to bring brand configuration into the app, and wrote the shell script that applies a brand's configuration before the build runs.
Result
A new branded app is a configuration change, not a fork. CI/CD builds every brand from the same source with its own settings.
  1. CMS Brand configuration colors · fonts · icons · assets · bundle ID
  2. Pre-build script Applies the brand to the project no source changes per brand
  3. CI/CD One build per brand same codebase, own store listing

Majoo

2020 – 2023

A point-of-sale app for phones and tablets, from one codebase

Problem
Majoo's business app for Indonesian SMEs (POS, inventory and analytics) was native Android. It had to move to Flutter and serve phones and tablets, whose layouts are very different, without separate implementations.
